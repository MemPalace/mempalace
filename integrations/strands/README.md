# MemPalace × Strands Agents Integration

Give any [Strands Agents](https://strandsagents.com) agent persistent long-term memory powered by [MemPalace](https://github.com/MemPalace/mempalace).

Three tools turn a stateless agent into one that **remembers** across sessions — without cloud APIs, without cost, fully offline.

## Install

```bash
pip install strands-agents mempalace
```

## Quick Start

```python
from strands import Agent
from strands.models import BedrockModel
from memory_tools import MEMORY_TOOLS

agent = Agent(
    model=BedrockModel("us.amazon.nova-lite-v1:0"),
    tools=MEMORY_TOOLS,
)

# Agent stores content (calls mp_memory_store internally)
agent("Remember that I prefer dark mode.", user_id="alice")

# Later — agent recalls (calls mp_memory_recall internally)
agent("What are my preferences?", user_id="alice")
# → "From memory: • prefers dark mode"
```

Works with any Strands-compatible model: Bedrock (Nova, Claude, Titan), OpenAI, Anthropic, local vLLM/Ollama — swap one line.

## Tools

| Tool | Context | Purpose |
|------|---------|--------|
| `mp_kb_search` | No | Search knowledge base (docs, guides, reference material) |
| `mp_memory_recall` | Yes | Recall past conversations and preferences (per-user) |
| `mp_memory_store` | Yes | Store user content verbatim for future sessions (per-user) |

### mp_kb_search

```python
mp_kb_search(query="how to configure notifications", wing="docs")
```

Searches a specific wing of the palace. Use for documentation, guides, or any pre-loaded knowledge.

### mp_memory_recall

```python
mp_memory_recall(query="user preferences", tool_context=...)
```

Searches the `conversations` wing, scoped to the current user's room. Returns memories from past interactions.

### mp_memory_store

```python
mp_memory_store(content="User prefers CSV over Excel for exports", tool_context=...)
```

Stores content **verbatim** in the `conversations` wing under the current user's room. The drawer document is byte-for-byte identical to the input — no summarization, no rewriting. Available in all future sessions.

## User Isolation

Each user's memories live in a separate **room** within the palace:

```
conversations/          ← wing
├── user-alice/         ← room (Alice's memories only)
├── user-bob/           ← room (Bob's memories only)
└── user-default/       ← fallback room
```

Isolation is enforced server-side via `ToolContext.invocation_state["user_id"]`. The agent cannot access another user's room — the user_id is injected by the caller, not generated by the LLM.

```python
# Server injects user_id — agent sees tools but not the isolation logic
agent("what do I prefer?", user_id="alice")   # → searches room user-alice
agent("what do I prefer?", user_id="bob")     # → searches room user-bob
```

## Architecture

```
Any LLM (Bedrock / OpenAI / vLLM / Ollama)
         │
         ▼
   Strands Agent (decides when to remember/recall)
         │
         ├── mp_kb_search ────────────┐
         ├── mp_memory_recall ──────┤── MemPalace Python API
         └── mp_memory_store ───────┘
                                    │
                                    ▼
                              ChromaDB (local)
                              Embeddings (CPU)
                              Zero cloud. Zero cost.
```

## Production Notes

- **Lazy loading**: The embedding model (~300 MB) loads on first tool call, not on import.
- **Graceful degradation**: If mempalace is not installed, tools return clear error messages (agent continues working without memory).
- **Thread safety**: Palace operations are safe for concurrent access (ChromaDB WAL mode).
- **Write locking**: Store operations use `mine_lock` to prevent duplicate drawers from concurrent agents.
- **Backup**: Palace is a directory — back it up with any file-level tool (rsync, tar, etc.).

## Pre-loading Knowledge

Mine documents into the palace before starting your agent:

```bash
mempalace mine ~/docs --wing knowledge
```

Then `mp_kb_search(query, wing="knowledge")` finds relevant passages instantly.
