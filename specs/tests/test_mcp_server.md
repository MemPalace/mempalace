# Behavior Spec — `tests/test_mcp_server.py`

This file is a test suite that pins the externally observable behavior of the MemPalace MCP server (`mempalace.mcp_server`). Each section below describes the *contract the server under test must satisfy*, as asserted by these tests. The contracts are language-agnostic; an implementer can re-derive the required server behavior from them.

The suite imports test fixtures `config`, `palace_path`, `kg`, `seeded_kg`, `collection`, `seeded_collection` (defined elsewhere via `conftest.py`) and patches module globals to isolate the palace and knowledge graph from real data (tests/test_mcp_server.py:L76-L100).

## Process startup / environment hygiene

The server entry point `main()` reads JSON-RPC lines from stdin until EOF; an empty stdin causes the read to return empty and the loop to exit cleanly (tests/test_mcp_server.py:L42-L64). When `main()` runs, it MUST remove `PYTHONPATH` from the process environment so any spawned subprocess starts clean; after `main()` returns, `PYTHONPATH` is `None` (tests/test_mcp_server.py:L26-L73). At package import time (before `main()`): `PYTHONPATH` must be preserved verbatim (env strip must NOT happen in package `__init__`), and `sys.path` must already have the leak sentinel filtered out (tests/test_mcp_server.py:L44-L73).

Importing `mempalace.mcp_server` must NOT create `~/.mempalace` (the kill-switch directory) nor `knowledge_graph.sqlite3` as a side effect; WAL and KG creation are deferred to first write/use (tests/test_mcp_server.py:L2995-L3027, tests/test_mcp_server.py:L3058-L3080).

## Cold-start logging (`MEMPALACE_LOG_FILE`)

`_init_logging` runs at module import. With `MEMPALACE_LOG_FILE` unset (or whitespace-only, which counts as unset after trimming), only a stream handler is attached to the root logger (tests/test_mcp_server.py:L148-L176). With a valid path, a file handler is attached and the startup banner `"MemPalace MCP Server starting"` is persisted into that file (tests/test_mcp_server.py:L178-L184). When the path is invalid (missing ancestor directory, or contains an embedded newline), the server MUST NOT crash, MUST emit a warning containing `"could not be opened"` and the literal env var name `MEMPALACE_LOG_FILE` (and the offending directory name) to stderr, and MUST NOT create the file; exit code stays 0 (tests/test_mcp_server.py:L186-L199, tests/test_mcp_server.py:L425-L438). The file handler is opened eagerly at import (not lazily); the failure warning is emitted BEFORE the startup banner, proving eager open (tests/test_mcp_server.py:L440-L459).

## Cold-start eager warmup (`MEMPALACE_EAGER_WARMUP`)

A fresh-install pre-check gates warmup on the existence of `chroma.sqlite3` in the palace dir (tests/test_mcp_server.py:L201-L213). Warmup is OFF by default: when the env var is unset, the collection is not opened (tests/test_mcp_server.py:L232-L240). Explicit falsy values `0`, `false`, `no`, `off`, `FALSE` skip warmup with no warning (tests/test_mcp_server.py:L242-L256). Unrecognized values (`tru`, `maybe`, `ENABLED`, `2`) skip warmup AND log a warning containing `"not recognized"` (tests/test_mcp_server.py:L258-L268). Truthy values `1`, `true`, `YES`, `On` open the collection AND invoke `col.query(...)` with probe text containing `__mempalace_warmup_probe__` and `n_results=1`; on success, stderr logs `"embedder + HNSW ready"` plus `palace=<path>` (tests/test_mcp_server.py:L270-L316).

Warmup is fail-soft and never blocks the server (exit code 0 in all error cases). On a fresh palace dir with no `chroma.sqlite3`, warmup skips before any client open, logs `"nothing to warm"`, and MUST NOT create `chroma.sqlite3` (preserving the "no on-disk state before init" / incremental-only contract); no retry tracebacks (`attempt N/2 failed`) leak (tests/test_mcp_server.py:L317-L358). If the collection accessor returns `None`, stderr logs `"_get_collection returned None"` and NOT the success line (tests/test_mcp_server.py:L360-L372). If opening the collection raises, stderr logs `"collection open failed"`, the raised message, `palace=<path>`, and `error=RuntimeError` (tests/test_mcp_server.py:L374-L391). If the warmup query raises, stderr logs `"warmup query failed"` plus the message/palace/error class, and the same diagnostic is also persisted to the `MEMPALACE_LOG_FILE` (tests/test_mcp_server.py:L393-L423).

## JSON-RPC dispatch (`handle_request`)

`handle_request(request)` is the dispatch layer. `initialize` returns a result whose `serverInfo.name == "mempalace"` and echoes the request `id` (tests/test_mcp_server.py:L466-L471). Protocol version negotiation: a supported client `protocolVersion` is echoed back (tests/test_mcp_server.py:L473-L495); an unknown version falls back to the newest supported version `SUPPORTED_PROTOCOL_VERSIONS[0]` (tests/test_mcp_server.py:L497-L509); a missing version uses the oldest `SUPPORTED_PROTOCOL_VERSIONS[-1]` (tests/test_mcp_server.py:L511-L515).

`ping` returns the request `id` and an empty `result` object `{}` (tests/test_mcp_server.py:L523-L528). Any `notifications/*` method returns `None` (no response) — including `initialized`, `cancelled`, `progress`, `roots/list_changed` (tests/test_mcp_server.py:L517-L521, tests/test_mcp_server.py:L604-L615).

`tools/list` returns `result.tools`, a list that includes at least `mempalace_status`, `mempalace_search`, `mempalace_add_drawer`, `mempalace_kg_add` (tests/test_mcp_server.py:L530-L539). No tool's `inputSchema` may contain a top-level `anyOf`/`oneOf`/`allOf` combinator (cross-tool constraints are enforced at dispatch instead, to avoid Anthropic Messages API rejection) (tests/test_mcp_server.py:L541-L553).

`tools/call` with `arguments: null` returns a result, not a hang (tests/test_mcp_server.py:L555-L570). An unknown tool name returns error code `-32601` (tests/test_mcp_server.py:L572-L582). Missing/invalid `params` (`None`, `{}`, `{"arguments": {}}` — i.e. missing `name`) return error `-32602` with message containing `"Invalid params"` (tests/test_mcp_server.py:L584-L596). An unknown method with an `id` returns `-32601`; without an `id` returns `None` (tests/test_mcp_server.py:L598-L622). `method` of `None` or missing returns `None` when no `id`, and `-32601` when an `id` is present (tests/test_mcp_server.py:L624-L638). A non-object payload (`None`, list, string, number, bool) returns exactly `{"jsonrpc":"2.0","id":null,"error":{"code":-32600,"message":"Invalid Request"}}` (tests/test_mcp_server.py:L640-L649).

A successful `tools/call` wraps the tool result as `result.content[0].text` containing a JSON string (e.g. status produces a JSON object with `total_drawers`) (tests/test_mcp_server.py:L651-L668).

## Read tools

`tool_status()` returns a dict with `total_drawers`, `wings`, `rooms`, optionally `backend`/`hnsw_capacity`/`vector_disabled`/`partial`. On a valid palace whose `chroma.sqlite3` exists but the drawers collection has not been created, status returns `total_drawers: 0` (not "No palace found") (tests/test_mcp_server.py:L675-L692). An empty palace returns `total_drawers: 0` and `wings: {}` (tests/test_mcp_server.py:L694-L702). With seeded data, `total_drawers == 4` and `wings` includes `project` and `notes` (tests/test_mcp_server.py:L704-L712). With no palace at all, status returns a dict containing `error` (tests/test_mcp_server.py:L948-L953).

Non-Chroma backends omit HNSW fields: `sqlite_exact` and `qdrant` backends report `backend` and `total_drawers` but no `hnsw_capacity`, and `vector_disabled` is not `True` (tests/test_mcp_server.py:L713-L780). Drawers whose metadata is `None` are tallied under `unknown/unknown` without crashing or setting `partial: True` (tests/test_mcp_server.py:L782-L812).

`tool_list_wings()` returns `wings` mapping wing→count (`project: 3`, `notes: 1` for the seeded fixture) (tests/test_mcp_server.py:L814-L820). `tool_list_rooms(wing=...)` returns `rooms`; unfiltered lists all rooms across wings, filtered by `wing` only that wing's rooms (tests/test_mcp_server.py:L822-L838). `tool_get_taxonomy()` returns `taxonomy` as a nested wing→room→count map (tests/test_mcp_server.py:L839-L846).

Overview tools (`tool_status`, `tool_list_wings`, `tool_list_rooms`, `tool_get_taxonomy`, `tool_graph_stats`) MUST answer from a SQLite cross-tab fast path and MUST NOT page all metadata through the storage client (`_fetch_all_metadata`/`graph_stats`/`_get_collection` must not be reached) (tests/test_mcp_server.py:L848-L875, tests/test_mcp_server.py:L900-L937). The fast path still maps missing wing/room to the literal `unknown` (not the SQL COALESCE placeholder `?`) (tests/test_mcp_server.py:L877-L898).

`tool_graph_stats()` aggregates from SQLite: drawers in a `general` room and wing-less drawers are excluded (matching the per-drawer filter); it returns `total_rooms`, `tunnel_rooms`, `total_edges`, `rooms_per_wing`, and `top_tunnels` (a list of `{room, wings, count}`) (tests/test_mcp_server.py:L900-L946).

## None-metadata safety

`_safe_meta(x)` coerces `None`, non-dict strings, and lists to `{}`, and passes through real dicts unchanged (tests/test_mcp_server.py:L979-L988). `_get_result_ids` normalizes a `None` `ids` value (dict or dict-like) to `[]` (tests/test_mcp_server.py:L1389-L1397). When the backend returns `None` for a metadata cell, the following tools tolerate it without `AttributeError`: `tool_get_drawer` (missing metadata → `wing`/`room` empty strings, content preserved) (tests/test_mcp_server.py:L990-L1010); `tool_list_drawers` (None entry → empty-string wing/room) (tests/test_mcp_server.py:L1012-L1032); `tool_update_drawer` (old meta coerced to `{}`, new wing applied) (tests/test_mcp_server.py:L1034-L1055); `tool_delete_drawer` (audit-log path tolerates None, delete proceeds, `delete(ids=[...])` called once) (tests/test_mcp_server.py:L1057-L1076); `tool_check_duplicate` (None matches render with sentinel `wing`/`room` of `"?"` and empty content rather than crashing) (tests/test_mcp_server.py:L1457-L1490).

## Search tool

`tool_search(query=...)` returns `{results: [...]}` with each result carrying `text`, `wing`, `room`, ranked by relevance (tests/test_mcp_server.py:L1083-L1092). `wing=`/`room=` filter results to only that wing/room (tests/test_mcp_server.py:L1094-L1106). Legacy `min_similarity` is accepted via backwards-compat shim and takes precedence over `max_distance` when both are given (tests/test_mcp_server.py:L1108-L1122).

Path-traversal-style names are rejected with an `error` dict before any backend call: `tool_list_rooms(wing="../etc/passwd")`, `tool_search(room="../backend")`, `tool_list_drawers(wing="../notes")`, `tool_find_tunnels(wing_a="../project")` (tests/test_mcp_server.py:L1124-L1140, tests/test_mcp_server.py:L1272-L1288).

Transient index errors trigger exactly one cache-reset retry. An error message matching the HNSW-flush transient (`"Error finding id"`) or a stale-index error retries once: search is called twice, the cache reset is called once, the final result carries `index_recovered: True` (tests/test_mcp_server.py:L1142-L1170, tests/test_mcp_server.py:L1244-L1270). The retry queries the same configured collection name both times (tests/test_mcp_server.py:L1172-L1202). Non-transient errors (e.g. `"invalid query syntax"`) do NOT retry (called once, no `index_recovered`) (tests/test_mcp_server.py:L1204-L1222). If the transient persists past the retry, the second error is surfaced with no `index_recovered` (tests/test_mcp_server.py:L1223-L1242).

`tool_check_duplicate(content, threshold=...)` returns `is_duplicate` (true when a sufficiently-similar drawer exists at/above threshold) and `matches` (tests/test_mcp_server.py:L1480-L1509). When vector search is disabled (HNSW capacity diverged), it short-circuits without opening the collection and returns `is_duplicate: False`, `vector_disabled: True`, `vector_disabled_reason: "<message>"` (tests/test_mcp_server.py:L1511-L1528).

## Write-ahead log (WAL) contract

`wal._wal_log(operation, params)` appends one JSONL record to `_WAL_FILE`. Sensitive fields `content` and `query` are redacted (replaced with a value beginning `"[REDACTED"`); other fields (e.g. `safe`) pass through verbatim (tests/test_mcp_server.py:L1290-L1305). The directory is created lazily on first write (not at import); the record is JSON with `operation` and `params` keys (tests/test_mcp_server.py:L3029-L3046). On POSIX, the log file is created mode `0o600` and its parent directory mode `0o700` (tests/test_mcp_server.py:L3048-L3052).

## Write tools — drawers

`tool_add_drawer(wing, room, content)` returns `{success: True, wing, room, drawer_id, chunks}`; `drawer_id` starts with `drawer_<wing>_<room>_` (tests/test_mcp_server.py:L1312-L1326). Re-adding identical content returns `success: True` with `reason: "already_exists"` (idempotent; no second write) (tests/test_mcp_server.py:L1328-L1340, tests/test_mcp_server.py:L1373-L1387). If the idempotency pre-check read raises, the write fails (`success: False`, error contains `"Idempotency check failed before write"` and the cause) and no upsert is attempted (tests/test_mcp_server.py:L1342-L1371). If a write succeeds but the read-back misses, the result is `success: False` with error containing `"not readable"` (tests/test_mcp_server.py:L1399-L1417). Documents sharing a long (>100 char) header but differing in body get distinct `drawer_id`s (ID is a full-content hash) (tests/test_mcp_server.py:L1419-L1440).

Chunking (verbatim preservation): content of length `<= chunk_size` (including exactly `chunk_size`) produces one drawer with `chunks == 1` and no `chunk_ids` field (tests/test_mcp_server.py:L1826-L1841, tests/test_mcp_server.py:L1931-L1946). Oversized content is sliced into bounded chunks: `chunks > 1`, `chunk_ids` has length `chunks`, no stored document exceeds `chunk_size`, the chunks joined in `chunk_index` order equal the original content verbatim, and every chunk metadata carries `chunk_index` (contiguous `0..N-1`) and a shared `parent_drawer_id` equal to the returned logical `drawer_id` (tests/test_mcp_server.py:L1843-L1929). Re-adding identical oversized content is idempotent: `reason: "already_exists"`, no duplicate rows, the logical id is not stored as a row, and the last chunk id is the atomicity probe (tests/test_mcp_server.py:L1879-L1907).

Logical-id semantics: chunk rows are internal storage; `tool_get_drawer`, `tool_update_drawer`, `tool_delete_drawer`, `tool_list_drawers` all operate on the logical id. `get` returns the reassembled verbatim content plus `chunks`/`chunk_ids`; `list` counts the group as one drawer (`total == 1`, `count == 1`) reporting `chunks`; `delete` returns `chunks_deleted == chunks` and a subsequent `get` returns an error containing `"not found"`; `update` rewrites the whole group keeping the same logical id (tests/test_mcp_server.py:L1949-L2029).

`tool_get_drawer(id)` returns `{drawer_id, wing, room, content, metadata}`; an unknown id returns an `error` (tests/test_mcp_server.py:L1530-L1545). It MUST NOT leak absolute `source_file` paths: the response exposes only the basename, and neither the absolute path nor its parent directory appears anywhere in the serialized response (tests/test_mcp_server.py:L1547-L1584).

`tool_list_drawers(wing?, room?, limit?, offset?)` returns `{count, drawers, total?, limit?, offset?}`; supports wing/room filtering and pagination; a negative `offset` is clamped to `0` (tests/test_mcp_server.py:L1586-L1630).

`tool_update_drawer(id, content?, wing?, room?)` returns `success: True` and the new wing/room on change; updating content is observable via a subsequent get; an unknown id returns `success: False`; a no-arg call returns `success: True` with `noop: True` (tests/test_mcp_server.py:L1632-L1668).

`tool_delete_drawer(id)` returns `success: True` and removes the drawer (collection count decremented); an unknown id returns `success: False` (tests/test_mcp_server.py:L1442-L1455).

## Tunnels and hallways

`tool_create_tunnel(source_wing, source_room, target_wing, target_room, label?)` stores the wing slug verbatim (hyphens preserved); the returned `source.wing`/`target.wing` echo the slug, and `tool_list_tunnels` finds it under both hyphen and underscore queries (tests/test_mcp_server.py:L1670-L1695). A `ValueError` from the underlying create (e.g. missing target room) is surfaced as `{"error": "<message>"}`, not wrapped as an opaque internal error (tests/test_mcp_server.py:L1697-L1717).

`tool_list_hallways(wing?)` returns a list: all records with no wing, only the matching wing when filtered (tests/test_mcp_server.py:L1721-L1771). An invalid wing name (e.g. containing forward slashes) returns a dict with `error` (tests/test_mcp_server.py:L1773-L1782). `tool_delete_hallway(hallway_id)` returns `{deleted: True}` and removes an existing record, `{deleted: False}` for an unknown id (no error), and `{"error": "hallway_id is required"}` for empty/`None` id (tests/test_mcp_server.py:L1784-L1810). Both `mempalace_list_hallways` and `mempalace_delete_hallway` are registered in the public `TOOLS` registry, with `handler` pointing at the respective functions (tests/test_mcp_server.py:L1812-L1824).

## Knowledge-graph tools

`tool_kg_add(subject, predicate, object, valid_from, valid_to?, source_closet?, source_file?, source_drawer_id?)` returns `{success: True, triple_id}` (tests/test_mcp_server.py:L2036-L2046). `valid_to` round-trips into storage; a fact whose `valid_to` is in the past is reported `current: False` (tests/test_mcp_server.py:L2070-L2089). Provenance columns `source_closet`/`source_file`/`source_drawer_id` persist to the `triples` row (tests/test_mcp_server.py:L2091-L2121).

`tool_kg_query(entity, as_of?, direction?)` returns `{count, facts, as_of}` (tests/test_mcp_server.py:L2048-L2053, tests/test_mcp_server.py:L2258-L2279). `tool_kg_invalidate(subject, predicate, object, ended?)` returns `{success: True, ended}` where `ended` echoes the resolved date — the caller-supplied date when given, else today's ISO date, and NEVER the literal string `"today"` (tests/test_mcp_server.py:L2055-L2068, tests/test_mcp_server.py:L2123-L2149). `tool_kg_timeline(entity)` returns `{count, ...}` (tests/test_mcp_server.py:L2151-L2156). `tool_kg_stats()` returns `{entities, ...}` (tests/test_mcp_server.py:L2158-L2163).

Date validation at the MCP boundary: plain `YYYY-MM-DD` ISO dates are accepted; non-ISO strings (`"Jan 2025"`, `"March 2026"`, `"yesterday"`) are rejected with `success: False`/`error` naming the offending field (`valid_from`/`as_of`/`ended`) and mentioning `ISO-8601` (tests/test_mcp_server.py:L2167-L2200). Partial ISO dates (`"2026"`, `"2026-03"`) are rejected because lexicographic TEXT comparison would silently exclude facts; full `YYYY-MM-DD` passes (tests/test_mcp_server.py:L2202-L2216).

Canonical UTC datetimes `YYYY-MM-DDTHH:MM:SSZ` are accepted on `valid_from`/`valid_to`/`as_of`/`ended` and round-trip verbatim (tests/test_mcp_server.py:L2218-L2306). Non-canonical datetime forms — timezone offsets (`+02:00`, `-05:30`), fractional seconds (`.123Z`), space separator, and offset-less (`...T14:23:00`) — are rejected with `success: False`/`error` naming the field and mentioning `YYYY-MM-DDTHH:MM:SSZ` (tests/test_mcp_server.py:L2308-L2405).

## Diary tools

`tool_diary_write(agent_name, entry, topic?, wing?)` returns `{success: True, agent, entry_id, chunks}`; `agent_name` is normalized to lowercase in the returned `agent` and in storage (tests/test_mcp_server.py:L2412-L2430, tests/test_mcp_server.py:L2517-L2559). `tool_diary_read(agent_name, wing?)` returns `{total, entries}` where each entry has `topic` and `content`; an unknown agent yields `entries: []` (tests/test_mcp_server.py:L2412-L2439). Reads are case-insensitive over `agent_name` (writes as `Claude`/`CLAUDE` are readable as `claude`) (tests/test_mcp_server.py:L2517-L2559).

Two writes within the same second sharing a long prefix get distinct `entry_id`s and both are readable (tests/test_mcp_server.py:L2441-L2481). `tool_diary_read(wing="")` returns entries across all wings the agent wrote to; an explicit non-empty `wing` scopes to that wing only (tests/test_mcp_server.py:L2483-L2515). Diary entry chunking mirrors drawers: normal entry → `chunks == 1`, one stored document; oversized entry (e.g. 5000 chars with `CHUNK_SIZE == 800` → 7 chunks) → bounded chunks each `<= 800` chars, joined verbatim equal to the original, each carrying a shared `parent_entry_id` and contiguous `chunk_index` 0..N-1 (tests/test_mcp_server.py:L2563-L2634).

## Collection cache invalidation and reconnect

`_get_collection()` caches the open collection keyed on the palace `chroma.sqlite3` inode and mtime. A changed mtime or inode invalidates the cache and reconnects (tests/test_mcp_server.py:L2643-L2680). When `chroma.sqlite3` disappears, a cached collection is invalidated and `_get_collection(create=False)` returns `None` without opening a new client (no `make_client` call), and the cache state is reset (`_collection_cache is None`, `_palace_db_inode == 0`, `_palace_db_mtime == 0.0`) (tests/test_mcp_server.py:L2682-L2720).

`_get_collection(create=True)` on reopen MUST call `get_collection` first and only fall back to `create_collection`; it MUST NOT call `get_or_create_collection` (which can SIGSEGV on metadata mismatch) (tests/test_mcp_server.py:L2828-L2871). Both `get_collection` and `create_collection` (and the cache-miss reopen path) MUST be invoked with a non-`None` `embedding_function` (tests/test_mcp_server.py:L2873-L2927). `_get_collection` retries once on a transient open failure (clearing client/collection caches and rebuilding the client); two attempts run and the second succeeds — but if both attempts fail it returns `None` after exactly two attempts (tests/test_mcp_server.py:L2929-L2992).

`tool_reconnect()` returns `{success, message, drawers}`. With no collection available, `success: False`, message contains `"No palace found"`, `drawers: 0` (tests/test_mcp_server.py:L2722-L2733). On success, message contains `"Reconnected"` and `drawers` is the integer count (tests/test_mcp_server.py:L2735-L2745). Reconnect closes the shared backend for the configured palace path (and a previously-cached non-Chroma backend, closing both the selected and cached backend in order) (tests/test_mcp_server.py:L2747-L2826). Reconnect also drains the KG cache: it calls `close()` on each cached KG, clears `_kg_by_path` to `{}` even if a `close()` raises (tests/test_mcp_server.py:L3272-L3312). Reconnect clears the per-process HNSW quarantine gate for the palace path; `_get_client` re-runs `_prepare_palace_for_open` (re-arming quarantine checks) on reconnect (tests/test_mcp_server.py:L3314-L3363).

## Knowledge-graph lazy per-path cache

`_get_kg()` resolves the palace path (from `MEMPALACE_PALACE_PATH`) and caches one `KnowledgeGraph` per canonical path in `_kg_by_path`. Two calls with the same resolved path return the same instance; different paths give different instances (tests/test_mcp_server.py:L3082-L3113). Rotating `MEMPALACE_PALACE_PATH` between tool calls routes each call to the correct tenant's KG file — tenant B never sees tenant A's facts (tests/test_mcp_server.py:L3115-L3145). Concurrent `_get_kg()` for one path yields exactly one instance (thread-safe) (tests/test_mcp_server.py:L3256-L3270).

`_canonicalize_kg_path(p)` collapses symlink aliases and Windows drive-letter casing to a single key, composing as `normcase(realpath(p))` in that order (tests/test_mcp_server.py:L3529-L3611).

`_call_kg(op)` captures the canonical path once, then runs `op(kg)`. If `op` raises a `sqlite3.ProgrammingError` ("closed database"), it evicts the closed instance under the captured key and retries once with a fresh KG; the fresh instance is cached (tests/test_mcp_server.py:L3365-L3393). Non-`ProgrammingError` exceptions propagate without retry (tests/test_mcp_server.py:L3395-L3417). If the retry also hits a closed DB, it gives up after exactly one retry (two `op` invocations) rather than looping (tests/test_mcp_server.py:L3419-L3442). Both `_get_kg` calls during retry receive the captured path (even if `_resolve_kg_path` drifts), so eviction lands under the captured key (tests/test_mcp_server.py:L3444-L3499). An `OSError` from `_canonicalize_kg_path` at the top propagates unchanged and `op` is never run (tests/test_mcp_server.py:L3501-L3527).

## Structured errors and watchdog

`_internal_tool_error(req_id, tool_name, exc=None)` returns `{"jsonrpc":"2.0","id":req_id,"error":{"code":-32000,"message":"Internal tool error"}}`. With no `exc`, the error has no `data` field; with an `exc`, `error.data.error_class` is the exception class name and `error.data.message` contains the exception message (tests/test_mcp_server.py:L3155-L3186). The `handle_request` exception branch passes the caught exception through, so a tool-handler exception surfaces as `-32000` with `error.data.error_class` set (tests/test_mcp_server.py:L3188-L3225).

`tool_sync()` on a `MineAlreadyRunning` lock returns `{success: False, error: "...another mine is in progress...", error_class: "LockHeldByOtherProcess"}` (tests/test_mcp_server.py:L3227-L3247). An invalid `MEMPALACE_MCP_IDLE_HOURS` makes `_mcp_idle_timeout_secs()` return `0.0` (disabling the idle auto-exit watchdog) (tests/test_mcp_server.py:L3249-L3254).

## Param-shape diagnostics on dispatch

A dispatch-level missing-required-argument `TypeError` surfaces as `-32602` with the quoted missing param name and the tool name in the message; two missing args list both quoted names without a syntactically broken " and " in the lead-in (tests/test_mcp_server.py:L3617-L3698). A handler-internal `TypeError` whose function name does not match the dispatched handler, a non-`TypeError` handler exception, and the "unexpected keyword argument" shape all stay generic `-32000` with message exactly `"Internal tool error"` and no internal helper/param names or filesystem paths leaked (tests/test_mcp_server.py:L3641-L3678, tests/test_mcp_server.py:L3782-L3834).

Diary-write `content` aliases `entry`: a `content`-only call remaps to `entry` (consuming the alias so `content` is not passed to the handler); when both are present, `entry` wins and `content` is dropped; an explicitly supplied even-empty (`""`) `entry` wins over `content` (the alias only fills when `entry` is absent or null, not merely falsy) (tests/test_mcp_server.py:L3700-L3780).

An unknown parameter name (a kwarg not in the tool schema, e.g. `text=` instead of `content=`) returns `-32602` with message containing the quoted offending kwarg, `"Unknown parameter"`, and the tool name (and NOT a "Missing required" symptom); two unknowns list both quoted names (tests/test_mcp_server.py:L3837-L3885). The internal transport kwarg `wait_for_previous` is popped before dispatch and must NOT be flagged as unknown for a normal handler (tests/test_mcp_server.py:L3887-L3914). Handlers that explicitly accept `**kwargs` bypass the schema filter and keep accepting unknown kwargs without rejection (tests/test_mcp_server.py:L3916-L3936).
